方法1（直接接続）の設定

通常は「DHU から直接」で接続できます。つながらない場合は「内蔵リレー経由」を選ぶと、 socat TCP-LISTEN:5277,fork TCP:スマホIP:5277 と同じ中継を Linux Auto 自身が行います（socat のインストールは不要）。

方法2（ADB）の設定

adb tcpip 方式は通常 5555。ワイヤレスデバッグ方式はスマホに表示される「IP アドレスとポート」のポート番号を入力します。

① はスマホを一度だけ USB で接続して実行します（スマホを再起動すると元に戻るため、再起動後は再実行が必要です）。 テザリングの親機になっているスマホではワイヤレスデバッグを ON にできない機種があるため、テザリング運用では ① の方式がおすすめです。

Android 11 以降の「ワイヤレスデバッグ（ペアリング）」を使う場合

スマホの「開発者向けオプション」→「ワイヤレスデバッグ」→「ペア設定コードによるデバイスのペア設定」に表示されるポートとコードを入力します。

導入・設定ガイド

Android SDK、Desktop Head Unit (DHU) の導入から Wi-Fi（テザリング）接続、Linux の自動起動設定までステップ順に解説します

1

Android SDK と Google DHU の導入

Linux Auto を動かすには、Google公式の desktop-head-unit バイナリ（パッケージ名: extras;google;auto）が必要です。 下の「自動セットアップ」を使うか、方法A / 方法B のいずれかで手動インストールしてください。

かんたん: 自動セットアップ（いちばんおすすめ）

ボタンを押すだけで、次の作業をまとめて行います（数分かかります）。

  1. Java 17 以降（sdkmanager の実行に必要）が無ければ自動でインストール
  2. 最新版の Android SDK Command-line Tools を repository2-1.xml で調べてダウンロード
  3. extras;google;auto（DHU）と platform-tools（adb）をインストール
  4. DHU に実行権限を付与し、必要なライブラリ（libc++ など）が無ければ自動でインストール
  5. 設定画面の「desktop-head-unit のパス」を保存し、 ~/.android/headunit.ini を書き込み
ℹ️ 足りないパッケージがある場合は、デスクトップにパスワード入力のダイアログが表示されます。 Java や DHU に必要なライブラリ（libc++）のインストールには管理者権限が必要なためです。ログインに使うパスワードを入力してください。 ダイアログが表示されない環境では、ログに表示されるコマンドをターミナルで実行してから、もう一度実行してください。

コマンドラインから実行する場合（画面のボタンと同じ処理です）：

cd ~/LinuxAuto
python3 setup-sdk.py --yes

主なオプション: --no-install-deps（足りないパッケージを自動でインストールしない）、--no-platform-tools、--reinstall、--reset-ini、--sdk-root パス。 足りないパッケージのインストール時は sudo のパスワードを入力します。 --yes を付けない場合は、ライセンスを画面で確認して y を入力します。一覧は python3 setup-sdk.py --help で確認できます。

方法A: ターミナルから手動で導入（Android Studio不要）

巨大な Android Studio を入れずに、コマンドラインツールだけで最速インストールする手順です。

  1. 必要なJava環境と解凍ツールをインストールします： 
    sudo apt update && sudo apt install -y openjdk-17-jdk-headless unzip wget
  2. 最新版のコマンドラインツール（Android SDK Command-line Tools）のファイル名を調べます：

    ZIP のファイル名（commandlinetools-linux-<ビルド番号>_latest.zip）はバージョンごとに変わるため、 Google が公開している SDK のパッケージ一覧 https://dl.google.com/android/repository/repository2-1.xml から、最新版（cmdline-tools;latest）の Linux 用ファイル名を取り出します。 

    CMDLINE_ZIP=$(wget -qO- https://dl.google.com/android/repository/repository2-1.xml \
  | sed -n '/<remotePackage path="cmdline-tools;latest">/,/<\/remotePackage>/p' \
  | grep -o 'commandlinetools-linux-[0-9]*_latest\.zip' | head -n 1)
echo "$CMDLINE_ZIP"

    commandlinetools-linux-16111833_latest.zip のように表示されれば成功です（数字は最新版に合わせて変わります）。何も表示されない場合はネットワーク接続を確認してください。

  3. Android SDKディレクトリを作成し、手順2で調べたファイルを https://dl.google.com/android/repository/ からダウンロードして配置します（手順2と同じターミナルで続けて実行してください）： 
    mkdir -p ~/Android/Sdk/cmdline-tools
cd ~/Android/Sdk/cmdline-tools
wget "https://dl.google.com/android/repository/${CMDLINE_ZIP}" -O cmdline-tools.zip
unzip cmdline-tools.zip && mv cmdline-tools latest && rm cmdline-tools.zip

    展開したフォルダは必ず ~/Android/Sdk/cmdline-tools/latest/ という構成にしてください（mv cmdline-tools latest の部分）。この構成でないと sdkmanager が動きません。

  4. extras;google;auto（DHU）をインストールします： 
    yes | ~/Android/Sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=$HOME/Android/Sdk "extras;google;auto"
  5. バイナリに実行権限を付与します： 
    chmod +x ~/Android/Sdk/extras/google/auto/desktop-head-unit

方法B: Android Studio (GUI) から導入する場合

  1. Android Studio を起動し、スタート画面の 「More Actions」→「SDK Manager」（または設定内の「Languages & Frameworks」→「Android SDK」）を開きます。
  2. 上部のタブで 「SDK Tools」 を選択します。
  3. 一覧の中にある 「Android Auto Desktop Head Unit emulator」 にチェックを入れます。
  4. 右下の 「Apply」 をクリックしてダウンロード・インストールを完了させます。
  5. インストール完了後、以下のパスに実行ファイルが配置されます： 
    chmod +x ~/Android/Sdk/extras/google/auto/desktop-head-unit
💡 パスの確認: インストール完了後、本アプリの「設定」画面を開き、「標準パス自動探索」ボタンを押すだけで自動認識されます。
2

スマートフォン側の設定 (Android Auto 開発者モード)

Androidスマートフォン側で、車載通信サーバー（ヘッドユニットサーバー）を起動する必要があります。

スマホ側の操作手順

  1. スマートフォンの「設定」アプリを開き、検索バーで 「Android Auto」 を検索して開きます。
  2. 画面を一番下までスクロールし、「バージョン」 という項目を 10回連続でタップ します。
  3. 「開発者向け設定を有効にしますか？」とポップアップが出るので 「OK」 をタップします。
  4. 画面右上の 「︙（メニュー）」 をタップし、「ヘッドユニットサーバーを起動」 を選択します。
  5. スマートフォンとPCをUSBケーブルで接続します（充電専用ケーブルではなく、データ通信対応ケーブルをご使用ください）。
3

Wi-Fi（テザリング）で接続する場合の準備

Linux 端末をスマホのテザリング（Wi-Fi アクセスポイント）に接続して、ケーブルなしで Android Auto を使う手順です。 メイン画面で「Wi-Fi接続」を選び、方法1（ヘッドユニットサーバーへ直接・既定） か 方法2（ADB） を選択します。通常は方法1のままで OK です。

⚙ 以下の手順に出てくる「ネットワーク状態」「手動入力」「ADB 接続ポート」「① / ② のボタン」「ペアリング」「疎通確認」「接続経路」は、メイン画面の Wi-Fi接続 →「詳細設定を表示」 を押すと表示されます。普段は接続先スマホの IP と接続モードだけを確認して「接続開始」を押せば OK です。

共通: テザリングに接続してヘッドユニットサーバーを起動

  1. スマホの「テザリング（Wi-Fi アクセスポイント）」を ON にし、Linux 端末をそのアクセスポイントに Wi-Fi 接続します。
  2. スマホの Android Auto 設定 →「︙」→ 「ヘッドユニットサーバーを起動」 をタップします（通知が表示されれば起動中です）。
  3. メイン画面の「接続先スマホ」にスマホの IP アドレス が表示されていることを確認します（「見つかりません」の場合はテザリングへの接続を確認してください）。
💡 スマホの IP は自動検出されます。 テザリング中は Linux 端末のデフォルトゲートウェイ＝スマホ本体です。 Android 11 以降はテザリングのアドレスが接続のたびに変わることがあるため、「自動（テザリング親機を検出）」のままの利用をおすすめします。 自宅ルーター等の同一 LAN で使う場合は「手動入力」にスマホの IP を入力してください。

方法1: ヘッドユニットサーバーへ直接接続（おすすめ・追加機材なし）

  1. 共通手順でヘッドユニットサーバーを起動します（ADB や USB デバッグは不要です）。
  2. メイン画面で「方法1」を選び、「接続開始」を押します（つながらない場合のみ 「ヘッドユニットサーバーの疎通確認」 で原因を確認します。疎通確認は接続を1回使うため、確認後はスマホでヘッドユニットサーバーを停止→起動し直してから接続してください）。
  3. DHU が --adb=<スマホIP>:5277 でスマホへ直接接続します。スマホのロックを解除し、Android Auto の確認画面が出たら許可してください。

手動で行う場合のコマンド：

./desktop-head-unit --adb=<スマホIP>:5277

※ DHU から直接つながらない場合は、接続経路を 「内蔵リレー経由」 に切り替えてください。 socat TCP-LISTEN:5277,fork TCP:<スマホIP>:5277 と同じ中継を Linux Auto が行うため、socat のインストールは不要です。
※ 疎通確認で「接続を拒否しました」となる場合、ヘッドユニットサーバーが起動していないか、お使いの端末・Android Auto のバージョンでは Wi-Fi 側からの接続を受け付けていない可能性があります。その場合は方法2をご利用ください。
※ 接続はできても DHU が「Waiting for phone...」のまま進まない場合（約20秒で画面に警告が出ます）は、 スマホでヘッドユニットサーバーを停止→起動し直してください。それでも進まない端末では方法2をご利用ください。

方法2: ADB（Wi-Fiデバッグ）＋ポートフォワーディング（開発・テスト向け）

adb が必要です。未導入の場合はインストールします：

~/Android/Sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=$HOME/Android/Sdk "platform-tools"

【A: adb tcpip 方式】テザリング運用ではこちらがおすすめ

  1. スマホの「開発者向けオプション」で USB デバッグ を ON にします。
  2. スマホを一度だけ USB で接続し、メイン画面の 「① USB経由で TCP/IP モードを有効化」 を押します（スマホに許可ダイアログが出たら「許可」）。
  3. USB ケーブルを外し、「② Wi-Fi で接続テスト」 で「connected to …」と表示されることを確認します。
  4. 「接続開始」を押すと、adb connect → adb forward tcp:5277 tcp:5277 → DHU 起動が自動で行われます。

※ スマホを再起動すると TCP/IP モードは解除されるため、② からやり直す前に ① を再実行してください。

手動で行う場合のコマンド（<スマホIP> はゲートウェイの IP）： 

adb tcpip 5555            # USB 接続中に一度だけ
adb connect <スマホIP>:5555
adb forward tcp:5277 tcp:5277
./desktop-head-unit

【B: ワイヤレスデバッグ方式】Android 11 以降・同一 Wi-Fi ルーター環境向け

  1. 「開発者向けオプション」→ ワイヤレスデバッグ を ON にします。
  2. 「ペア設定コードによるデバイスのペア設定」を開き、表示されたポートとコードをメイン画面の「ワイヤレスデバッグ（ペアリング）」欄に入力して「ペアリング」を押します。
  3. ワイヤレスデバッグ画面の「IP アドレスとポート」のポート番号を ADB 接続ポート に入力し、「接続開始」を押します。

※ テザリングの親機になっているスマホでは、機種によってワイヤレスデバッグを ON にできません。その場合は A の方式を使用してください。

4

サーバーをサービスとして自動起動する（systemd）

Linux Auto のサーバー（app.py）を systemd の ユーザーサービス として登録すると、 PC にログインしたとき自動でバックグラウンド起動し、常駐するようになります。 画面（このWebUI）を閉じてもサーバーと Android Auto 接続は止まりません。

🛈 現在のサーバー起動方式: 確認中...

1. サービスを登録する（初回のみ）

以下を実行するだけで、サービスの作成・自動起動の有効化・即時起動まで完了します： 

cd ~/LinuxAuto
chmod +x install-service.sh
./install-service.sh

※ ~/.config/systemd/user/linux-auto.service が作成されます。sudo は不要です。
※ 以前の方式（~/.config/autostart/linux-auto.desktop）が残っている場合は、二重起動を防ぐため自動で無効化されます。
※ ./start.sh で手動起動したサーバーが動いている場合は、先に Ctrl+C で終了してから登録してください。

2. 電源投入直後（ログイン前）から起動したい場合（任意）

通常はログイン時に起動します。車載PCなどでログイン前からサーバーを立ち上げておきたい場合は --boot を付けて登録します （loginctl enable-linger が設定されます）： 

./install-service.sh --boot

※ Android Auto の画面（DHUのウィンドウ）はデスクトップに表示されるため、実際に接続するのはログイン後です。 自動ログインを有効にしておくと、電源を入れるだけで接続できる状態になります。

3. サービスの操作コマンド

  • 状態確認： 
    systemctl --user status linux-auto
  • ログをリアルタイム表示： 
    journalctl --user -u linux-auto -f
  • 再起動（git pull 等でコードを更新した後は必ず実行）： 
    systemctl --user restart linux-auto
  • 停止 / 起動： 
    systemctl --user stop linux-auto
systemctl --user start linux-auto
  • 登録解除（自動起動をやめる）： 
    ./install-service.sh --uninstall
5

起動アイコン（画面を開くだけ）を登録する

デスクトップ / アプリメニューの「Linux Auto」アイコンは、この画面を開くためだけのランチャー（open-ui.sh）です。 サーバーはサービスとして常駐しているので、アイコンを押すたびにサーバーが起動し直すことはありません。

1. アイコンを登録する

cd ~/LinuxAuto
chmod +x install-desktop-shortcut.sh
./install-desktop-shortcut.sh

※ 以前のバージョンでアイコンを登録済みの場合も、もう一度実行してください（アイコンの起動先が open-ui.sh に切り替わります）。

2. アイコンを押したときの動作

  1. サーバーが応答していれば、そのままブラウザ（またはPWA）でこの画面を開きます。
  2. サービスが停止していた場合は、systemctl --user start linux-auto で起動してから画面を開きます。
  3. サービス未登録の場合のみ、サーバーを一時的にバックグラウンド起動します（ログ: ~/.cache/linux-auto/server.log）。
💡 ブラウザを閉じても接続は切れません。 Android Auto を終了したいときは、この画面の「切断 / 停止」ボタンを押してください。

参考: ターミナルで直接実行する場合

デバッグ時などは、サーバーをフォアグラウンドで起動（./start.sh）したり、DHUを直接実行（./connect.sh）したりできます。サービスが動いている間に ./start.sh を実行すると、二重起動せず画面だけが開きます。

About Linux Auto

プロジェクトおよび開発者情報

Linux Auto

Version 1.0.0 (Ubuntu & Kubuntu Edition)

Google DHU（Desktop Head Unit）だけではコマンドラインでの操作や設定が必要で難易度の高かった Ubuntu系列OSへのAndroid Auto接続を、ワンクリック＆GUIでサポートするツールです。

プロジェクト名 Linux Auto
開発者 エノキ電気 ENOKI ELECTRONICS
ホームページ https://enoki.xyz
GitHub https://github.com/jikantoki/LinuxAuto

主な機能と特徴

  • ワンクリック有線接続: desktop-head-unit --usb をバックグラウンドで安全に起動
  • 切断時10秒自動復帰: USBケーブルが抜けてプロセスが落ちても、10秒間自動的に再接続を試行
  • GUI設定エディタ: ~/.android/headunit.ini（解像度・DPI・タッチ・FPS）を直感的に設定
  • Zero-Dependency 設計: Python 3標準ライブラリ100%で動作し、Ubuntuのバージョンアップ等による依存破壊を排除
